Retrieval-Augmented Question Answering on TriviaQA is a research-oriented natural language processing project focused on Retrieval-Augmented Generation for open-domain question answering. The repository implements a complete RAG pipeline on the TriviaQA dataset, specifically in the Wikipedia setting, where the system must retrieve useful evidence passages from long Wikipedia articles and then use a language model to generate a short, grounded answer. Rather than being only a coding demo, the project is structured like a compact experimental study: it includes data preparation, multiple retrieval strategies, prompt design, model comparison, end-to-end evaluation, and a written report that documents the full methodology and results.

The repository is organized around two main notebooks. Data.ipynb handles dataset preparation: it downloads and extracts TriviaQA, builds train, validation, and test splits, flattens questions and answer aliases into a cleaner format, and creates a document store of Wikipedia evidence files that can be indexed efficiently. Project.ipynb contains the full RAG implementation. It loads the prepared data, chunks long documents into overlapping passages, implements sparse BM25 retrieval, dense retrieval with Sentence-Transformers embeddings, and a hybrid pipeline with cross-encoder reranking, then feeds the retrieved context into different instruction-tuned language models for answer generation. The repository also includes a Report.pdf with the full explanation of the project and its experimental findings.

From a technical point of view, the pipeline is well structured and covers the main components expected in a modern RAG system. The evidence documents are cleaned and split into chunks of 350 words with overlap, so that answer-bearing spans are less likely to be lost across chunk boundaries. Retrieval is tested with three setups: lexical BM25, dense semantic retrieval, and BM25 followed by reranking with a cross-encoder. On the generation side, the project compares several compact open-weight models, including Phi-3, Gemma, Mistral v0.3, Llama 2, Qwen2, and Qwen3, all used in quantized form to stay compatible with limited Google Colab GPU resources. The prompting strategy is also treated as an experimental variable, with zero-shot, few-shot, and span-extraction style prompts evaluated systematically.

A strong point of the project is that it does not stop at implementation. It measures retrieval quality through Recall@K and downstream QA quality through the official TriviaQA Exact Match and F1 metrics. According to the report, the hybrid retriever based on BM25 plus reranking is the strongest retrieval setup, especially at small K, where ranking quality matters most. Among the generator models, Mistral v0.3 emerges as the best overall option in the tested setting. The final selected configuration uses BM25 plus reranker, Top-10 retrieved passages, and zero-shot prompting with Mistral v0.3. In the report, this setup reaches 76.10% Exact Match and 83.89% F1 on the 7,900-question validation set, and 83.16% Exact Match and 90.20% F1 on the held-out verified test set.

Overall, this repository shows the full lifecycle of a practical RAG project: preparing a real QA dataset, building a retriever over external documents, integrating the retriever with multiple LLM readers, evaluating alternative configurations, and selecting a final recipe that balances quality and computational cost. It is therefore useful both as an implementation example and as a compact research project on how retrieval choices, prompt design, model scale, and context depth affect open-domain question answering performance. For the full technical details, experimental tables, prompt templates, and discussion of limitations, the accompanying report should be considered the primary reference.
